AgentDesk 准备材料说明

这些是学习用的虚构数据和设计规格。当前没有 Agent 运行时、权限引擎、沙箱或自动评分器；JSON 里的规则不会自己执行。先完成第一周查询练习，再逐步把规格实现为代码与测试。

文件用途
tickets.json两个租户、三条工单，练 Python JSON 读取、筛选和授权。
documents.json四篇资料，包含一篇故意含伪造指令的安全测试材料；只当数据读取。
job_events.json四条模拟任务事件；给调查结论提供可验证证据。
sample_south.csv故意缺少 currency 列的样本，用于后续隔离文件分析。
actors.example.json测试身份。正式实现必须从服务器认证上下文获取身份。
policy.example.json权限、审批绑定、预算与审计字段示例，不是已生效的安全配置。
eval_cases.seed.jsonl12 个开发集规格样例，包含正常、越权、注入、超时、回执丢失与恢复。

第一次练习

  1. 用 Python 读取 tickets.json，解释列表与字典。
  2. 编写 get_ticket(actor, ticket_id)，身份由测试上下文传入。
  3. u-n-viewer 可以查询 T-1001，不能读取 T-2001。
  4. 用断言验证正常、缺失与无权。返回内容不要泄漏其他租户的字段。
  5. 关闭 AI 对话，把规则改为增加一个资源可见性条件，再独立验证。

如何扩展为评测

先将 acceptance_checks 转成确定性断言。fault_injection 是将来模拟器应支持的条件名称，目前尚未实现。每个 trial 重置数据，记录工具轨迹与最终业务状态。12 个样例都是开发集，不是留出集，也不构成生产安全证明。
