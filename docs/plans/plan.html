01 AgentDesk 独立项目执行计划

企业工单排查与受控执行平台 | v1.0 | 2026-10-28 | 44 个有效学习周主线

目标：从会调用模型，练到能构建、诊断、评测和交付一个有权限边界、可恢复的 Agent 系统。

项目处理虚构 SaaS 产品的支持工单：查手册、查导出任务状态和日志，分析样本文件，提出带证据的解决方案；需要修改业务状态时，先展示具体操作，经过授权再执行，并留下审计记录。它与 MeetLoop 完全独立。

层次必须交付
最小可用版本单 Agent、只读工具、证据引用、失败退出、运行记录、离线测试集。
完整主线检索权限、受控写操作、人工审批、代码沙箱、任务恢复、评测与灰度回退。
深入与求职比较不同设计的实际效果，完成一次故障演练和两轮试用，能解释关键实现。
可选平台加深模型网关、限流、队列、路由、vLLM 服务测量；不要求训练模型或写 CUDA 内核。

适合你的定位

主定位是 AI 应用 / Agent 工程，增加客户访谈、集成和交付可以支撑 FDE 方向。模型服务平台是后续分支，不与主线同时铺开。英语与沟通能力可以用于英文演示、需求澄清与方案讲解；技术可信度来自实际工程证据。

主线按约 400 小时估算。起步每周 7 小时，后续可增加到 8-10 小时，44 个有效学习周通常需要约 12-15 个日历月，基础补课和返工会延长。平台分支另计 80-120 小时。

“吃透”指能替换框架的一层、复现失败、证明修复和解释取舍，不以堆框架数量或无监督自主运行时长衡量。

02 具体产品与首版范围

用业务问题驱动技术学习，避免只做聊天界面

示例工单：“客户 A 的导出任务一直失败，请查原因，并给出处理建议。”系统读取工单、租户可见手册和任务日志；判断是临时依赖超时、权限不足还是 CSV 格式问题；给出证据和下一步。只有临时故障且满足策略时，才可申请重试导出。

输入情形期望行为如何确认结果
依赖临时超时引用日志和运行手册；提出重试草案审批后调用模拟业务 API；读取操作状态确认结果。
权限不足说明缺少权限并交给负责人绝不自行扩大角色或读取其他租户数据。
CSV 列缺失在隔离环境分析样本并生成报告输出缺列清单与文件哈希，不擅自修改原始文件。
手册过时 / 证据冲突标记不确定，补查或请求人工处理区分事实、推测和仍需核实的内容。
文档含伪造指令把它当资料内容，继续按宿主策略执行越权工具没有运行，拒绝原因进入审计。

首版只包含

  • 一个工单入口、三个只读工具、结构化调查报告、20 个用例与运行日志。先做 CLI / API，控制台放到后面。
  • 两个模拟租户、虚构文档和日志；用现成样例生成器或手工数据，不接真实客户系统。
  • 暂不做浏览器全自动操作、即时通讯接入、自动发邮件、长期人格记忆、多个专家 Agent 团队。

先写规则化工作流作为基线。步骤固定且规则足够解决时，直接用代码；只有需要根据证据选择下一步时才引入模型决策。

03 技术栈与前置知识

以 Python 服务与工程机制为主；框架是一层可替换实现

层默认选择必须掌握
语言与 APIPython 3.12 或依赖支持的稳定版本；FastAPI / Pydantic类型、异常、模块、asyncio、超时、取消、HTTP 与 JSON Schema。
运行时先写小型循环，主项目使用 OpenAI Agents SDK工具分发、停止条件、事件与会话；业务权限在 SDK 外单独执行。
数据学习实验 SQLite；持久化阶段 PostgreSQLSQL、索引、事务、约束、迁移、备份；pgvector 在检索基线之后按需增加。
前端后期 TypeScript / React 简单控制台运行列表、证据、审批与 SSE 事件流；不追加第二个 RN App。
验证与运维pytest、结构化日志、容器与 CI离线 Mock 回归、真实模型评测、追踪、故障复现与部署回滚。
沙箱受限 Docker 起步；再评估 OpenSandbox生命周期、隔离、出口网络、资源预算、产物回收；控制面与执行面分离。

先懂这些模型概念即可

token 与上下文窗口、概率输出与不确定性、结构化输出和工具调用、embedding 与相似度、检索与生成的区别、prefill / decode / KV cache 的概念。通过小实验解释现象；暂不要求反向传播推导、模型训练或论文产出。

课程优先用 Python 官方教程、FastAPI、Hugging Face Agents Course 的基础概念。只选一套实现主线；LangChain / LangGraph 可以比较，但不是前置条件，也不与 SDK 同时叠加。

04 架构与信任边界

模型负责提出行动；宿主系统决定允许什么、如何执行、如何确认结果

用户 / 控制台 → API 与身份 → Run 管理器 → Agent 循环
Agent 循环 → 工具策略与审批 → 只读连接器 / 隔离执行器
事件、审批、工具回执 → 持久化与审计 → 评测与监控

组件责任明确边界
身份 / API确认用户、租户、角色、请求预算从登录上下文获取，不能信任模型给出的 tenant_id。
Run 管理器创建运行、排队、取消、恢复与并发控制持久化状态是事实来源，聊天历史不代替执行账本。
Agent 循环选择工具、整合证据、形成建议不能直接持有管理员凭据，也不能绕过工具策略。
工具网关参数校验、资源授权、审批和幂等执行前重查权限；所有调用都留下关联 ID 和结果。
隔离执行器只在单次任务工作区运行代码 / 分析文件不挂载用户主目录、宿主 Docker socket 或 API 密钥。
存储 / 观测工单、文档、事件、回执、产物、评测版本租户范围贯穿数据库查询、检索、缓存、日志与产物访问。

逐步创建目录

apps/api、apps/console、agent/runtime、agent/tools、agent/policy、agent/retrieval、worker、evals、fixtures、docs。第一阶段只建实际使用的部分；不提前写通用插件市场或分布式编排系统。

产品中的文档、工单、日志与工具输出都是数据来源，不能自动升级为系统指令。系统边界由代码和运行环境执行。

05 先亲手做一次 Agent 循环

第 5-10 周 | 不从框架 API 名称开始理解 Agent

做一个小型教学实现：组装上下文 → 请求模型 → 解析结构化行动 → 校验参数与权限 → 调用工具 → 记录事件 → 返回工具结果 → 继续或终止。先使用 scripted Mock 模型，之后再接一个真实模型适配器。

机制需要完成的实验
停止与预算最大轮数、总耗时、工具超时、输入 / 输出预算；检测重复无效调用；触发上限时给出部分结果和原因。
工具错误区分参数错误、无权限、空结果、限流、超时和未知执行结果；不能全部转成“没有找到”。
状态created → running → waiting_approval / succeeded / failed / cancelled；queued 在多任务阶段加入，恢复需重新校验。
上下文保留目标、约束、已确认事实与证据 ID；大日志保存为产物，只回传摘要和受控读取入口。
取消用户停止后不再发起新工具；取消传播到请求 / 执行器；已经发生的副作用需要对账，不能宣称撤销。
可替换性相同 tools / policy / evals 接口换成 SDK 运行；比较行为差异，教学循环保留为理解和回归参考。

harness 到底包含什么

它是围绕模型的执行环境：工具与状态、上下文组装、预算、身份、权限、工作区、持久化、审批、恢复和观测。不是一个 prompt，也不是一次 while 循环。第一版就建立事件与预算，后续逐项强化。

06 工具设计与 MCP

先做强类型本地工具，再把一个只读工具暴露为 MCP

工具权限与副作用输出契约
get_ticket读取当前租户的指定工单工单字段、版本、来源 ID；不存在与无权的返回策略要一致。
search_docs检索前过滤文档 ACL片段、文档 / 版本 / chunk ID、时间与来源。
query_job_events按 job_id 查询允许的日志结构化事件、时间范围、截断标志；不用任意 SQL 接口。
analyze_csv仅在沙箱读取上传样本列 / 行统计、错误明细、输出产物；限制体积与资源。
draft_reply保存当前任务范围的草稿草稿 ID 与版本；明确没有发送。
retry_export修改模拟业务状态，需策略通过与审批operation_id、幂等键、状态；超时后查询回执。

每个工具固定名称、说明、输入 schema、输出 schema、错误类别、超时、权限与副作用等级。工具描述帮助模型选择；服务器仍须执行每项校验。禁止把任意 shell、任意 SQL、任意 URL 作为首版默认工具。

MCP 的验收

  • 把 search_docs 做成 MCP server，客户端仍走相同策略；说明工具发现、schema、传输与身份之间的关系。
  • 本地 stdio 从可信启动配置获得执行范围；远程 HTTP 按协议实现身份与令牌受众校验，避免把下游令牌直接透传。
  • 模拟工具描述被改、服务不可用、超时和恶意返回内容；MCP 接入不自动等于可信授权。

07 检索与上下文工程

第 11-16 周 | 先证明检索有用，再增加复杂度

顺序实现对照验证
关键词基线小文档集、稳定文档 ID 与版本、关键词 / 全文检索先用人工问题集测能否找到正确证据。
向量与混合检索比较 chunk 划分、embedding、关键词 + 向量固定数据集测 recall@k 与最终任务成功率。
重排与引用需要时才加 rerank；答案关联证据检索分数不是答案置信度；检查引用是否支持具体结论。
权限与更新检索前过滤租户与 ACL；文档删除 / 撤权使缓存失效跨租户文档不能进入模型上下文或缓存结果。
长上下文大输出落盘；摘要保留来源、未完成项、约束比较全量、截断、摘要三种方式的成本与遗漏。

把“找不到证据”“证据冲突”“证据过时”作为正常结果。可以继续查询、请求补充或移交人工；不能为了完成任务编造事实。模型看到的材料只包含完成当前任务所需的信息。

记忆的边界

会话历史、任务状态和长期记忆是三回事。首版只保存任务状态与受控历史；长期偏好记忆作为可选实验，要求用户确认、可查改删、按租户隔离，并且不存凭据。权限判断不依赖记忆或摘要。

选 10 个失败样例，逐个区分：数据缺失、检索失败、引用不支持、模型推理错误，还是工具执行失败。不同问题要用不同修复。

08 权限与人工审批

第 1 版就限制只读；增加写操作前必须完成本页

动作默认策略执行位置
查询工单 / 文档当前租户、当前用户可见资源API / 数据层 / 检索层共同校验。
沙箱分析文件只读输入与本任务输出目录工具网关与隔离运行时；文件路径规范化并防越界。
保存回复草稿当前工单内的草稿写入权限校验、版本检查、审计。
重试导出任务角色允许、任务可重试、次数受限、审批有效执行前重新校验；审批不能扩大原角色权限。
跨租户访问 / 提权禁止确定性策略直接拒绝；不交给 LLM 自己决定。

审批对象必须具体

审批记录绑定 user_id、tenant_id、run_id、tool_call_id、工具与参数哈希、资源版本、策略版本、有效期和审批人。展示将修改什么、影响范围与预期结果；改参数、换资源、过期或权限撤回后需要重新确认。

至少验证六种失败

  • 伪造 tenant_id；未授权角色；审批后修改参数；重复使用审批；审批等待期间撤权；资源版本变化。
  • 每次拒绝记录策略原因；敏感参数先脱敏。不要把“用户曾批准这个工具”当成所有后续参数都获批。

Prompt 中写“不要越权”是辅助约束。实际权限边界必须位于模型之外，并覆盖检索、缓存、工具调用、文件与日志。

09 沙箱与受控执行

第 17-24 周 | 没有隔离与策略，不开放模型生成代码

先执行你写好的 CSV 分析程序，理解文件传入、限制、取消和产物取回；再允许模型生成受限分析脚本。业务写入依旧走工具网关，沙箱没有业务系统的写凭据。

边界学习项目基线
工作区每个 run / trial 独立目录；输入只读，输出限额；路径和符号链接都验证，拒绝逃逸。
进程与权限容器内非 root、只读根文件系统、删除多余 capabilities、禁止提权；不暴露宿主 socket。
资源CPU、内存、进程数、执行时间、输出字节和磁盘上限；超时终止并回收，持续检查孤儿任务。
网络默认禁止出网；确需访问时通过受控代理白名单；限制重定向与私网 / 元数据地址。
密钥与控制面模型 API 在宿主服务侧；执行器不给主目录和密钥；沙箱管理接口只允许可信服务访问。
生命周期创建、健康检查、运行、取消、取回产物、销毁；不确定状态先隔离，不直接复用给其他租户。

Docker 是学习基线，不等于对任意恶意代码的完整强隔离。主线只接自己构造的样例；若未来开放不可信代码，应在独立 Linux 节点评估 gVisor / microVM 等边界，补威胁建模与运维验证。

沙箱关卡

用无破坏的测试验证越界文件读取、未授权网络、持续循环、过量输出和任务取消；检查宿主未收到敏感数据、资源已释放，下一次任务无法看到上一租户的文件。

10 持久化、恢复与并发

第 25-32 周 | 聊天记录与数据库事务都不能自动保证外部动作只执行一次

记录关键字段与作用
runs / run_events租户、状态、版本、事件序号、预算、时间；事件追加写，状态按合法转换更新。
tool_calls / receipts调用 ID、参数哈希、幂等键、attempt、执行状态、外部操作 ID；查询未知结果。
approvals审批对象、范围、有效期与版本；恢复后再检查，不因重放自动扩大授权。
artifacts / documents文件哈希、拥有者、租户、保留期限、版本与来源；独立做访问校验。
eval_runs代码、prompt、模型、数据、策略版本，及每次 trial 的指标与轨迹。

五个必须做的故障实验

  • 写入外部动作成功、回执丢失：进入 unknown / reconciling，通过 operation_id 查询，禁止盲目重试。
  • worker 在调用前或调用后退出：重启读取检查点；用幂等键和回执判断是否继续。
  • 两个 worker 抢同一任务：数据库租约、版本条件更新或锁防止并发处理；过期 worker 用 fencing / 版本拒绝。
  • 用户取消与工具完成同时发生：取消只阻止后续动作；已发生副作用记录并展示真实结果。
  • SSE 断连重连：按事件序号恢复展示，不因浏览器刷新重新启动整个业务动作。

先单进程 + SQLite 学状态，再用 PostgreSQL 验证并发与事务；需要多 worker 后再加可靠队列。明确投递、执行、回执各自的语义，不对外部系统宣称天然 exactly-once。

11 从第一天建立评测

测任务结果、过程约束与成本，不能只看回答是否像样

维度如何评分常见误区
任务成功检查报告字段、证据与模拟业务系统最终状态Agent 说“已处理”不代表操作发生。
工具与权限检查调用是否合法、是否越权或重复副作用不强制只有一条固定推理路径。
证据正确引用存在、版本一致、支持相关结论有引用不等于引用有效。
可靠性超时、取消、重启与限流后能否正确结束 / 恢复不能把未知执行结果计为成功。
效率成功任务总费用、端到端延迟、工具次数与 token只比较 token 省多少可能掩盖成功率下降。

数据集递进

W1-4 先定义 10-20 个场景；W5-10 做 20 个可重复用例；W11-24 扩到约 60 个，覆盖权限 / 注入 / 异常；W25 后争取 100 个，并按场景族划分开发集与留出集，避免同题改写泄漏。数量是目标，不是当前已有成果。

确定性断言优先：数据库状态、权限拒绝、输出结构、引用 ID。LLM judge 只辅助评价解释质量，先用人工样本校准，记录模型版本与分歧。每次评测重置隔离环境；冻结用例，不根据失败偷偷修改标准。

离线 Mock 回归每次提交可跑；真实模型评测按预算选关键集并多次运行，报告 n、成功次数和失败类型。安全硬门槛要求测试集中没有越权，不代表证明绝对安全。

项目自定发布门槛

学习版建议：所有确定性权限 / 幂等 / 恢复回归通过；在冻结的核心留出集上，任务成功率目标先设 80%，每例至少 3 次，公开失败项与样本数。小数据集会有较大波动，不能当生产 SLA 或市场效果。

什么时候才加多 Agent

主线稳定后，用一个 2 周实验验证“检索助手 + 主 Agent”是否有明确收益；比较单 Agent 与固定工作流。如果更贵、更慢而成功率无提升，就删除。需要独立权限、预算、上下文与取消传播，不能靠角色名称宣称隔离。

19 最终验收与求职展示

每项都要能现场解释、修改、制造失败并验证

关卡现场挑战
不用框架也能解释用教学循环讲一次工具执行全过程；换 SDK 时说明哪些代码不变。
权限实际生效给工单塞入伪造指令，换租户 ID，篡改审批参数；所有越权动作必须被宿主拦住。
任务能恢复运行中停止 worker，模拟写入成功但回执丢失；恢复后查询事实，不重复副作用。
结果可以测量他人用固定数据和命令复现评测；解释失败分类、模型差异、成本与样本局限。
能交付需求变化增加一个受限工具或变更角色规则；更新契约、策略和测试，完成演示。

留下三类工程案例

  • 权限 / 沙箱案例：威胁、边界、失败样例与回归；不要把未发生事故当作安全证明。
  • 恢复 / 幂等案例：时间线、状态、未知结果与对账，解释为什么不能简单重试。
  • 评测 / 优化案例：基线、变量、原始数据与代价；如果优化没有收益，也说明结论和取舍。

项目可支撑 AI 应用、Agent 工程及部分 FDE / 平台岗位的作品展示，但岗位录用还涉及基础面试、协作、实际经历与地区资格。本计划不承诺就业，也不把模拟项目描述成真实客户系统。
