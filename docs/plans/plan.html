01 AgentDesk 开发与学习主计划

v2.1 | 2026-10-29 主次修订 | Agent / AI 应用核心；FDE / 平台附加

主路线：后端与确定性基线 → 单 Agent 与早期 harness → 检索与 Web → 审批、沙箱、恢复 → 评测和交付。

构建一个虚构 SaaS 支持工单调查助手：查工单、可见文档和日志，给出带证据的诊断；需要重试导出时先提出具体操作，审批后执行并核实回执。它与 MeetLoop 的业务、仓库、数据库和部署完全独立。

已有准备不能视为完成
公开仓库、课程与源码地图、虚构数据、12 个开发集规格、策略设计示例。Agent 运行时、权限执行、沙箱、自动评分器、真实模型评测和部署均未实现。
本版统一阶段、工时、验收与岗位差距；补 Web 基础、数据生命周期和 FDE 交付。你的 Python / SQL 独立能力、环境和实际可用 API 仍需 A0-A2 验证。

核心是 Agent 工程与 AI 应用：后端、LLM、工具、数据、权限、沙箱、恢复和评测。基本产品交付保留；FDE专项与模型服务平台为附加，不作为应用实习前置。

plan.source.json生成同版Markdown/HTML/PDF。旧v2.0及v1.0仅作历史；本版将FDE专项和模型平台明确设为选修，执行顺序与工时以本版为准。

03 A0-A1：后端基础与确定性工作流

A0 10-15h；A1 50-70h | 前期不需要模型 API 或 GPU

顺序实现任务完成后应能
Python 起点虚拟环境、模块、类型、列表 / 字典、异常；读取 tickets.json；pytest。独立改查询规则，区分没有数据、权限拒绝与程序故障。
数据与权限从可信测试身份查询；租户和资源 ACL 校验；SQLite 学 SQL，迁移到 PostgreSQL 前掌握事务 / 约束。u-n-viewer 能读 T-1001，不能读 T-2001；伪造参数不能改身份。
API 与连接器FastAPI / Pydantic、HTTP 状态与 schema、超时、有限重试、连接池与取消。一个受限只读 API 能被测试和 curl 调用；不把所有错误返回 200。
确定性基线固定步骤查工单 → 日志 → 规则手册 → 结构化结论；记录 run_id 与耗时。说明为什么此流程不需要 Agent；之后所有模型改进都与它比较。

学习阶段用明确的测试身份注入；它不是登录方案。A4 接用户入口前完成真正的服务端会话 / 身份校验；不能信任前端 header 中自报的 tenant_id 或角色。

A1 关卡

60 分钟独立增加一个只读查询接口、SQL 条件和无权测试；解释同步 / 异步边界与事务；从干净环境复现基线。基础卡住时补练，不按“第 5 周必须用模型”跳级。

04 A2：LLM 基础与自己的小循环

45-65h | 先 scripted Mock，再真实模型，再迁移一种 SDK

内容实验与产出
LLM 基础token / 上下文、随机输出、结构化输出、工具调用；对同一任务改变提示或上下文，解释输出变化。工具调用是模型建议，实际执行由宿主决定。
教学循环组装上下文 → 请求模型 → 解析动作 → 参数校验 / 授权 → 工具执行 → 记录结果 → 下一轮或终止。先只读，不做自动写入。
最早的 harness最大轮数、run / tool 超时、取消、输出字节上限、预算、重复无效调用检测；run_events 带序号并写入 SQLite，供追踪和后续回放。
主 SDK用同一业务工具迁移到 OpenAI Agents SDK，追一次 Runner / tool 调用。业务权限、数据与评测不依赖 SDK 类型；不并用多套编排框架。
真实模型小样本用固定 10-20 个开发场景，区分任务正确、证据、越权、停止、费用与延迟；记录模型 / prompt / 工具版本。

模型名称和价格不写死在两年计划里。开始真实调用前核对官方接口、依赖版本、可用账户和预算；日上限与单次上限显式配置。账号未就绪时可继续 Mock，不把 Mock 通过写成模型效果。

A2 过关：不靠框架说清完整循环；注入无效参数、重复工具和超时后能有限停止。解释 prompt、工具定义、工作流与 harness 各自解决的问题。

05 A3：RAG、引用与数据生命周期

40-60h | 先可解释的检索基线，再按测量决定 embedding / reranker

开发任务必须做的验证
摄取与数据契约文档 id、版本、来源、租户、ACL、更新时间；格式校验、去重、重复导入与失败重跑。
检索与生成分离先关键词 / SQL 基线；再尝试 embedding / 混合检索；分别统计检索命中、证据支持和最终任务结果。
权限贯穿全链路先限可见范围再返回候选；缓存键、检索日志、引用下载都带权限语义；命中文档不等于有读取权限。
更新、删除与过期修改文档版本后重建相关索引；删除与撤权后检索 / 缓存 / 引用不得继续暴露旧内容；保留必要审计而非复制秘密。
上下文与引用大结果限长并关联原始证据；事实 / 推断 / 未知分开；缺证据就报告不确定，不补造来源。

把外部文档、工单、日志和工具输出当资料。文档里的“忽略规则”“读取其他租户”不具备授权效力；宿主仍须阻止。摘要和上下文压缩可能丢信息，必须用前后任务结果对照验证。

在本阶段工时内留 4-6h，把一个只读工具包装为本地 stdio MCP 服务，用同一授权与错误断言比较调用；理解互操作协议不提供业务权限。远程 OAuth 与公开服务后置。

过关能力

给一条错误结论定位是摄取、检索、权限、上下文还是生成问题；展示一次文档更新 / 删除回归和一次跨租户检索拒绝。数据管道比盲目堆向量库更优先。

06 A4：真正补上 Web 与全栈链路

60-85h | 先 JS / TS / DOM / CSS，再 React 控制台

开发顺序需要学到的能力
Web 基础语义 HTML、表单、CSS 盒模型 / Flex / Grid、响应式、DOM 与事件；DevTools 的 Network / Console / Performance。
JS / TS / React闭包、Promise / 事件循环、联合类型；组件、表单、状态、effect 清理；先不用大型状态库。
控制台最小功能工单输入、运行列表、证据详情、取消按钮；加载 / 空 / 错误状态和基本键盘可访问性。
API 与身份真实服务端会话 / 身份验证；区分认证与授权；理解 CORS、cookie / token、CSRF 与 XSS 对所选方案的影响。
SSE 与测试用 A2 的持久化事件序号按 cursor 回放；刷新 / 断线不重复执行业务；组件测试与一次端到端流程。业务恢复在 A6 加深。

A4 首次做受控单实例部署与一轮试用：依赖锁定、离线测试 CI、配置外置、HTTPS 接入、健康检查和基础日志脱敏。A7 加深恢复与交付，不把首次部署全部拖到末期。

过关能力

手画浏览器 → HTTP → FastAPI → SQL → SSE 的链路；独立加一个表单字段并更新全链路校验；修复一次断线、过期会话或重复订阅问题。只做一个漂亮聊天窗口不能过关。

07 A5：工具权限与人工审批

55-80h | 先受控模拟业务写入，不接真实客户系统

边界实现和验收
身份与资源范围身份来自可信登录上下文；所有工具与资源操作执行租户 / ACL / 角色检查；默认拒绝，不把鉴权放进 prompt。
操作绑定审批记录绑定 actor、tenant、run、tool_call、工具名、规范化参数哈希、资源 / 策略版本、过期时间和批准人。
执行时复查审批后改参数、撤权、资源状态变化或超时都需重查；审批不能赋予角色原本没有的权限。
幂等与回执写工具使用 operation_id / 幂等键；业务执行与结果查询分开；重复投递必须关联同一业务操作。
前端与审计显示具体动作、参数、影响与批准 / 拒绝；记录关联 ID、决策原因和最终事实，敏感字段脱敏。

首先实现 draft_reply 与 retry_export 的模拟链路；draft 不自动发送。A5 先迁移到 PostgreSQL，验证迁移与事务，再保存操作记录和未知结果；不长期维护两套数据库。A6 加 worker 重启 / 租约加固。区分“请求发出”“已确认执行”和“结果未知”。

关卡：篡改审批参数、重复点击、等待时撤权、工具响应丢失；行为与业务数据均符合断言。policy.example.json 只是规格，只有对应代码和测试实现后才算生效。

08 A6-1：沙箱和执行边界

A6 共 80-115h，含下一页恢复；此页先控制范围

分两步做，不直接开放任意代码

  • 先用白名单 CSV 分析器执行固定逻辑；校验文件类型、路径、大小和输出上限。禁止通过路径遍历或符号链接逃出工作区。
  • 需要运行模型生成代码时，先完成隔离执行器：每 run 独立工作区、非 root、只读输入、CPU / 内存 / 进程数 / 时间限制、默认拒绝出口网络。
  • 不挂宿主主目录、Docker socket、云凭据或模型密钥；执行面仅得到任务所需数据；产物访问也检查租户和资源授权。
  • 验证超时终止、取消、文件隔离、网络拒绝与清理；监控孤儿进程 / 容器，下一 run 不能继承上次文件。

Docker 是学习基线，不是对任意敌对代码的完整安全证明。OpenSandbox 可作为后续执行器替换实验；先理解控制面与执行面，再比较实现。跨 Mac / Windows / Linux 的容器限制需在实际环境验证。

过关能力

解释宿主权限、容器限制、文件隔离和网络策略分别在哪里生效；安全测试读取的是专门构造的诱饵数据，不使用个人秘密。E09 / E10 对应文件分析与超时回收。

09 A6-2：持久化、恢复与不确定结果

从单进程 / 单 worker 起步；分布式框架不是先修课

要实现失败实验 / 证据
Run 状态机created / running / waiting_approval / succeeded / failed / cancelled；需要排队时再加 queued；明确允许转移与版本检查。
事件和检查点持久化运行目标、已完成步骤、审批、工具调用和回执；聊天文本不充当执行账本；恢复前重查身份和策略。
未知结果与对账远端成功而响应丢失时进入待核实；查询 operation_id 再决定后续。用模拟外部系统作为可验证事实来源。
并发与取消单 worker 跑通后再加 lease / fencing / version；旧 worker 不能覆盖新结果；取消与外部已执行事实分开。
重启与重复投递在执行前、远端成功后本地记账前、恢复后分别中断；重复投递 / 审批重放不产生重复副作用。

不能凭框架 checkpoint 宣称 exactly-once。对于不支持幂等或查询回执的外部系统，必须描述局限、人工核实或补偿策略；不能靠重复调用赌结果。

关卡：E05 / E06 / E11 / E12 的规格成为真实测试；展示 worker 重启与最终数据库状态一致。自己的状态机足够时，不追加工作流平台。

10 A7-1：评测与优化的方法

A7核心85-120h，含下一页应用交付；评测从A1起持续积累

层次何时 / 如何验证
确定性测试A1 起验证业务规则、SQL、权限、参数与预算；Mock 注入 429、超时、坏 JSON、重复投递。通过不等于模型有效。
开发集A2 起使用现有 12 个规格及新增任务；每次重置业务状态，记录输入 / 预期 / 工具轨迹 / 实际副作用。
留出评测A7 前冻结不同任务家族与表达的留出集，版本记录；公开后不能再声称秘密，调参用过的样本归入开发集。
指标任务达成、引用支持、约束违规、恢复正确率、人工介入率、费用、总耗时与 p50 / p95；小样本报告分母与重复次数。
优化对照固定模型 / 数据 / 环境，比较规则基线、检索方案、上下文、工具 schema 与缓存；一次改一个因素。

项目实验可先扩展到 30-50 个开发任务、20-30 个留出任务，按成本选择每题重复 3-5 次；这些是起始设计，不是行业合格线。先做确定性评分，模型裁判仅辅助，抽样人工校准。安全关键用例要求本轮全部通过，但不等于生产安全保证。

质量、时延和成本一起报告；不要求模型每次选完全相同的工具轨迹。不能只让模型给自己的回答打分，也不能把几个成功截图当成功率。

11 A7-2：AI 应用交付与选修边界
