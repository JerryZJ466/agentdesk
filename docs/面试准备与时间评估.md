# 学习时间与面试验收

审核：2026-10-29。阶段和工时统一来自 [当前主计划](plans/plan.md)。这些是基于任务拆分的个人规划估算，尚未测定你的独立能力，不是行业统计或录用承诺。

| 目标 | 从现在起累计有效时间 | 达标条件 |
| --- | --- | --- |
| MeetLoop 首轮 iOS 实习准备 | 180-260h，M0-M3 | 本地与网络闭环、UIKit、独立改题/排错、最小服务正确性 |

| AgentDesk 受控操作投递检查点 | 260-375h，A0-A5 | 增加动作绑定审批、幂等、回执丢失对账；按实际能力与JD判断 |

## 为什么调整旧估时

MeetLoop保留450-650h。Agent旧400-550h没有充分单列Web基础、真实身份/连接器、数据维护和交付返工，本版改为450-650h并给出逐阶段工时。旧PDF的44周/400h、平台80-120h及“第5周一定开始模型”不再有效。我们没有为维持旧截止日期压缩基础。

## 默认周安排

- 首轮iOS准备：MeetLoop 13h + AgentDesk 5h + 公共基础3h = 21h。
- M3过关后：MeetLoop 8h + AgentDesk 10h + 公共基础3h = 21h。
- 2026年11月至2027年2月底约17周，对应221h / 85h / 51h；目标M3中低区间、A1完成，遇假期顺延。
- 主线总900-1300h，项目18h/周，约50-73个有效周；M3过关即切换8h/10h、暂不重分配已完成项目时间时约52-75周，加10%-20%中断余量约14-21个月。18个月可争取中档，不保证两项高档全部完成。
- 每周超过21h的部分优先独立改题、回归和薄弱基础；实习期间以实际空闲为准，不自动沿用21h。

## 每四周检查一次

1. 不依赖AI整段生成，45-90分钟完成一个变更；正常查文档允许。
2. 复现一个新故障，用日志或断点定位，补回归；讲清仍未解决的限制。
3. 更新 [进度账本](PROGRESS.md)：实际小时、commit、运行方法和证据；通过后再开下一阶段。
4. 两次卡在同一基础时，下一周减功能、补一个最小实验；不靠换框架跳过问题。

公共基础具体安排在 [COMMON_FOUNDATIONS](COMMON_FOUNDATIONS.md)。先用 [START_HERE](START_HERE.md) 开始，不必等待两项目全部完成才投递。
